# Wakeup 기획서

## 1. 목적

Wakeup은 Windows와 macOS의 데스크톱 브라우저에서 화면이 꺼지지 않게 하는 단일 페이지 웹앱이다.

## 2. 제품 원칙

- 현재 절전 방지 상태와 사용자가 취할 수 있는 동작을 먼저 보여 준다.
- 서버 기능과 사용자 계정 없이 동작한다.

## 3. 기능 범위

### 3.1 절전 방지

- 페이지가 로드되면 기간 제한 없이 Screen Wake Lock을 자동 요청한다.
- 자동 요청이 브라우저 정책(예: 사용자 조작 필요)에 의해 거부되면 이를 오류가 아니라 시작 안내 상태로 표시하고, 사용자가 한 번의 조작으로 시작할 수 있는 버튼을 둔다. 사용자의 조작에서 나온 요청이 거부된 때에만 오류 상태로 표시하며, 거부 사유가 `NotAllowedError`이면 저전력·배터리 절약 모드와 전원 정책을 원인 후보로 안내하는 문구를 쓴다.
- 잠금이 운영체제나 브라우저에 의해 해제되면 즉시 화면 상태를 갱신한다. 얻은 직후(2초 이내) 연달아 3번 풀리면 자동 재요청을 멈추고 시작 안내 상태로 둔다.
- 페이지가 다시 보이는 상태가 되었을 때, 사용자가 중지하지 않았고 타이머가 끝나지 않았다면 잠금을 다시 요청한다.
- 사용자는 언제든 절전 방지를 직접 중지하거나 다시 시작할 수 있다.

### 3.2 타이머

- 기본값은 `제한 없음`이다.
- 제한 없음, 15분, 30분, 1시간, 2시간과 직접 입력을 드롭다운이 아닌 즉시 선택 버튼으로 제공한다.
- 직접 입력은 시간을 0~999, 분을 0~59의 정수로 받는다. 합계가 0이거나 입력 범위를 벗어나면 현재 화면 언어로 안내한다.
- 타이머는 Wake Lock이 실제 활성화된 동안에만 흐르고, 중지되거나 일시 해제된 동안에는 멈춘다.
- 백그라운드 타이머 제한의 영향을 피하기 위해 활성 구간의 시작 시각과 종료 시각 차이를 누적한다.
- 제한 시간이 설정되고 절전 방지가 진행 중이면 현재 시각 기준 예상 종료 시각을 시:분으로 함께 표시한다.
- 시간이 끝나면 Wake Lock을 해제하고 상태, 남은 시간 및 문서 제목을 즉시 변경하며, 짧은 알림음을 한 번 재생한다.
- 타이머가 끝난 뒤 시간을 다시 설정하면 대기 상태로 돌아간다. 절전 방지가 꺼진 상태에서 설정한 시간은 시작 버튼을 누르면 적용된다.
- 알림음은 첫 사용자 조작 뒤에 준비되므로, 아직 조작이 없는 창(작은 창)에는 그 안내를 알림음 영역에 표시한다. 알림음 크기는 타이머 영역의 슬라이더로 조절한다. 0에서는 미리 듣기를 비활성화하고 볼륨을 올리라는 안내를 표시한다. 브라우저가 오디오를 지원하지 않으면 조작을 비활성화하고 그 이유를 표시한다. 알림음 크기는 저장하지 않으며 타이머가 `제한 없음`이면 알림음 설정을 숨긴다.

### 3.3 시간 표시

- Wake Lock이 실제 활성화된 누적 시간을 `시:분:초`로 표시한다.
- 사용자가 중지하거나 브라우저가 잠금을 해제한 동안에는 누적 시간이 증가하지 않는다.
- 시작한 타이머는 `남은 시간`으로 표시한다. 절전 방지가 꺼진 상태에서는 새로 시작할 때 적용될 시간을 `다음 타이머`로 표시한다. 전체 화면 시계도 같은 값을 보여 준다.
- 페이지가 보이는 동안 잠금이 예기치 않게 해제된 횟수를 `중단 횟수`로 표시한다. 사용자가 다른 탭이나 창으로 전환해 멈춘 것은 세지 않는다. 중단이 1회 이상이고 상태가 `active`이면 상태 설명에 가능한 원인(저전력 모드, 배터리 절약 모드, 시스템 정책)을 포함한다.
- 사용자가 새 절전 방지 세션을 시작하거나 페이지를 다시 열면 누적 시간과 중단 횟수를 초기화한다.

### 3.4 언어

- 한국어와 영어를 지원한다.
- 언어 결정 우선순위는 URL의 `lang` 매개변수, 브라우저 언어, 한국어 기본값 순이다.
- 언어 전환 시 페이지를 새로고침하지 않고 URL의 `?lang=ko` 또는 `?lang=en`을 갱신한다.

### 3.5 오프라인 및 설치

- Service Worker로 앱 셸을 캐시해 온라인 방문 후 오프라인에서도 다시 열 수 있다. 설치 시 앱 셸 파일은 브라우저 HTTP 캐시를 거치지 않고 받으며, 활성화 시 이전 Wakeup 캐시를 정리한다.
- Web App Manifest로 지원 브라우저의 설치 기능을 제공한다.

### 3.6 검색 기본 정보

- 서비스명은 `Wakeup`, 한 줄 설명은 한국어 `브라우저에서 화면이 잠들지 않게.`, 영어 `Keep your screen awake in the browser.`를 사용한다.
- 검색 기본 정보는 설명적인 문서 제목, 메타 설명, 배포 주소의 canonical URL(`?lang=` 주소에서는 `app.js`가 자기 자신으로 갱신), 의미 있는 단일 `h1`에 더해 다음을 제공한다.
  - `index.html <head>`의 Open Graph·Twitter Card 메타. `og:image`는 `icons/icon-512.png`를 절대 URL로 쓴다.
  - `?lang=ko`·`?lang=en`·`x-default`를 가리키는 `<link rel="alternate" hreflang>`.
  - `application/ld+json` 구조화 데이터: `WebApplication`(무료 `Offer`, `applicationCategory: UtilityApplication`, 운영체제)과 열린 FAQ 섹션과 문구가 일치하는 `FAQPage`.
  - 루트의 `robots.txt`(전체 허용 + `Sitemap:` 경로), `sitemap.xml`(배포 URL + ko/en/x-default 대체 링크). 두 파일은 Service Worker `APP_SHELL`에 넣지 않는다.
- 구조화 데이터의 FAQ 문구는 기본 언어인 한국어 화면과 일치시킨다.

### 3.7 테마

- 라이트와 다크 두 가지 색상 테마를 제공한다. 기본값은 브라우저·운영체제의 `prefers-color-scheme`을 따른다.
- 상단의 테마 버튼(`aria-pressed`로 다크 여부 표시)으로 다크/라이트를 바꿀 수 있다. 작은 창을 열거나 닫을 때 선택한 값도 함께 전달한다. 이 선택은 세션 한정이며 저장하지 않으므로 페이지를 다시 열면 시스템 설정으로 돌아간다. 시스템 설정이 바뀌면 사용자가 선택하기 전까지 함께 따라간다.
- 두 테마 모두 본문·조작 요소의 명암비와 포커스 표시를 유지한다.

## 4. 화면 구성

단일 중앙 패널에 다음 요소를 위에서 아래 순서로 배치한다. 내부 영역은 반복적인 테두리와 구분선 대신 제목 크기, 글자 굵기, 색상과 충분한 여백으로 구분한다.

1. 서비스 이름, 한 줄 설명, 테마 버튼과 한국어/영어 전환 버튼
2. 현재 절전 방지 상태, 간단한 설명, 활성 누적 시간과 필요 시 남은 시간·예상 종료 시각·중단 횟수
3. 시작 또는 중지 버튼과 그 아래 Space 키 안내 한 줄. 미지원 브라우저에서는 절전 방지 조작과 시간 표시 대신 다른 데스크톱 브라우저에서 여는 방법을 안내한다.
4. 타이머 즉시 선택 버튼, 필요 시 직접 입력 영역, 종료 알림음 크기 슬라이더와 미리 듣기 버튼
5. 보조 버튼 행 — 아래 두 버튼을 한 줄에 나란히 두고(좁은 폭에서는 세로) 각각 한 줄 설명을 붙인다. 타이머는 시작·중지 버튼 바로 아래에 두어 첫 화면에서 보이게 하고, 보조 버튼은 그 아래에 둔다.
   - Wakeup을 별도의 작은 창으로 여는 보조 버튼 (팝업 창이나 설치된 앱에서는 숨김). 여는 시점에 opener의, 닫는 시점에 새 창의 타이머 선택·진행 중인 남은 시간·절전 방지 누적 시간·사용자의 시작 또는 중지 상태·언어를 같은 출처 `postMessage`로 서로 전달한다. 저장소는 쓰지 않는다.
   - `전체 화면 시계로 보기` 보조 버튼 — Fullscreen API로 전체 화면에 어두운 배경과 저휘도 텍스트로 현재 시각과 타이머 정보(3.3절)를 크게 표시한다. `Esc` 또는 클릭으로 복귀하고, 마우스가 멈추면 커서를 숨긴다. 초 단위 갱신 외의 애니메이션은 두지 않는다. 기존 상태 기계와 타이밍을 재사용하며 저장하는 값은 없다. 절전 방지가 켜져 있을 때 화면이 가려지면 일시 중단된다는 안내를 표시한다.
6. 항상 펼쳐진 `자주 묻는 질문`(FAQ) 섹션 — 질문/답변 5개, 구조화 데이터(`FAQPage`)와 문구 일치. 작동 조건·제한(탭이 보일 때만 작동, 덮개·OS 절전·화면만 끄기 불가), 배터리, 설치·브라우저, 개인정보를 모두 여기서 설명하고 같은 내용을 다른 영역에 반복하지 않는다.
7. 프로젝트 저장소(GitHub)로 나가는 링크

## 5. 상태 정의

- `requesting`: 절전 방지를 요청 중인 상태
- `prompt`: 사용자 조작이 필요한 상태. 자동 요청 거부, 반복 해제 또는 작은 창에 설정 응답이 없는 경우에 사용한다.
- `active`: Wake Lock이 실제 활성화된 상태
- `idle`: 사용자가 중지했거나 아직 시작되지 않은 상태
- `suspended`: 브라우저 또는 운영체제가 잠금을 해제한 상태
- `expired`: 설정한 타이머가 종료된 상태
- `unsupported`: 브라우저가 Screen Wake Lock API를 지원하지 않는 상태
- `error`: 요청이 실패한 상태

상태는 색상뿐 아니라 제목과 설명으로 구분하고, 변경 사항은 `aria-live` 영역으로 알린다.

## 6. 저장소

화면은 `index.html`, `styles.css`, `app.js`로 구성한다. 배포 파일 목록은 `scripts/build.mjs`, 오프라인 앱 셸 목록은 `sw.js`에 있다. 개발 가이드는 [AGENTS.md](../AGENTS.md)를 따른다.

## 7. 브라우저 제약

Wakeup 페이지가 가려지거나 백그라운드로 가면 브라우저가 Screen Wake Lock을 해제할 수 있다. 브라우저가 제공하는 범위는 화면 꺼짐 방지이며, 운영체제 절전이나 닫힌 노트북 덮개는 제어할 수 없다. 사용자 안내는 화면 상태와 FAQ에 표시한다.

## 8. 접근성 및 디자인 기준

- 본문과 조작 요소의 최소 글자 크기: 14pt
- 섹션 의미는 반복적인 상자와 구분선보다 타이포 위계와 여백으로 전달
- 충분한 명암비와 명확한 키보드 포커스 제공
- 상태를 색상에만 의존해 전달하지 않음
- 모든 입력 요소에 연결된 레이블 제공
- 의미 없는 애니메이션과 지속적인 움직임 사용 안 함
- 주요 동작(시작·중지)은 Space 키로도 실행할 수 있게 하되, 입력란·버튼·링크·요약에 포커스가 있으면 기본 동작을 방해하지 않음
- 한글 본문은 음절이 아닌 단어(띄어쓰기) 단위로 줄바꿈함(`word-break: keep-all`)
- 좁은 화면에서도 깨지지 않게 만들되 공식 지원 범위는 PC와 Mac으로 한정
- 타이머·알림음·직접 입력 영역이 나타나고 사라져도 위쪽 요소(특히 시작·중지 버튼)의 위치가 흔들리지 않도록 카드를 세로 가운데가 아닌 위로 정렬
